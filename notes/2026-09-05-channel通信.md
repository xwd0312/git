# 2026-09-05：channel 通信

## 今天学了什么

今天学习了使用无缓冲 channel 在 goroutine 之间传递金额、关闭 channel，以及使用 `for range` 持续接收数据。

## 运行过的代码

- 示例文件：`study/函数/13.channel.go`
- 运行结果：三个购物任务的金额全部进入 `moneyList`，示例正常结束，没有死锁。
- 本次运行得到 `moneyList [5 3 2]`；再次运行时顺序可能不同。

## 我的理解

```go
var moneyChan = make(chan int)
```

- 这是一个无缓冲的 `int` channel。
- 发送 `moneyChan <- money` 必须与某个接收操作配对，否则发送方会阻塞。
- `for money := range moneyChan` 会不断接收，直到 channel 被关闭。
- `close(moneyChan)` 表示不会再发送新数据，不是清空数据。

## 为什么当前代码不会死锁

- 主 goroutine 已经在 `range moneyChan` 中等待接收，所以每个 `pay` 的发送都有接收者。
- 每个 `pay` 在发送成功后调用 `Done()`。
- 单独的 goroutine 等待 `wait.Wait()`；三个任务全部完成后，它关闭 channel。
- channel 关闭后，主 goroutine 的 `range` 正常结束。

执行关系可以概括为：

```text
pay 发送金额 → main 接收金额 → pay 调用 Done
全部 Done → 关闭 channel → range 结束
```

## 容易混淆的点

- 无缓冲 channel 没有存放数据的队列，发送与接收需要交接。
- `range channel` 若一直等不到关闭，会永久阻塞。
- 一般由发送方或协调发送方的人关闭 channel，接收方不应擅自关闭。
- goroutine 的完成顺序不固定，因此 `moneyList` 中金额的顺序也不固定。
- 阻塞不一定等于死锁；只有没有任何可能解除阻塞的操作时，才形成死锁。
